## 1. Классификация собственной системы (Windows 11)

**Статус:** Домашнее задание № 2 выполнено.  
**Примечание:** Подробный конспект занятия, разбор шести функций ядра, хроника развития от ENIAC до Android и теоретический материал находятся в папке `theory/`.

**1. По назначению**
* **Значение:** Универсальная ОС общего назначения (клиентская/настольная).
* **Обоснование:** Предназначена для выполнения широкого спектра пользовательских задач: работа с документами, веб-серфинг, мультимедиа, программирование и игры. Она сбалансирована под интерактивную работу одного пользователя за ПК, в отличие от специализированных серверных или встроенных ОС.
* **Наблюдение:** На компьютере одновременно открыты браузер, VirtualBox и офисные приложения, система отзывчива к действиям пользователя.

**2. По числу одновременно работающих пользователей**
* **Значение:** Многопользовательская ОС (с ограничением на одновременные сессии).
* **Обоснование:** Архитектура Windows поддерживает создание изолированных учетных записей для разных пользователей со своими правами и окружением. Однако в десктопной версии одновременно в интерактивном режиме (локально) может работать только один человек.
* **Наблюдение:** В параметрах системы заведены разные учетные записи пользователей (локальный профиль Davit и учетная запись Microsoft).
* **Подтверждение:** ![Подтверждение конфигурации системы](system_proof.png)

**3. По типу интерфейса**
* **Значение:** Графический интерфейс (GUI) с поддержкой командной строки (CLI).
* **Обоснование:** Основное взаимодействие происходит через окна, меню и указатель мыши. При этом доступны мощные консольные среды управления (Терминал Windows, PowerShell, cmd.exe).
* **Наблюдение:** Вся работа ведется в оконном режиме Windows, панель задач закреплена снизу, управление интуитивно понятно.
* **Подтверждение:** ![Подтверждение конфигурации системы](system_proof.png)

**4. По способу организации вычислительного процесса**
* **Значение:** Многозадачная ОС с вытесняющей многозадачностью и разделением времени.
* **Обоснование:** ОС способна параллельно выполнять сотни процессов и потоков. Планировщик ядра Windows распределяет кванты процессорного времени между потоками и принудительно прерывает (вытесняет) их для обеспечения плавности интерфейса.
* **Наблюдение:** В Диспетчере задач отображается одновременное выполнение сотен фоновых процессов, служб Windows и пользовательских программ без взаимной блокировки.
* **Подтверждение:** ![Подтверждение конфигурации системы](system_proof.png)

**5. По типу архитектуры ядра**
* **Значение:** Гибридное ядро (архитектура NT).
* **Обоснование:** Сочетает свойства монолитных акций и микроядер. Часть компонентов (планировщик, управление памятью) работают в защищенном режиме ядра для скорости, но архитектура сохраняет модульность.
* **Наблюдение:** Драйверы видеокарты или внешних устройств могут перезапускаться без падения всей операционной системы.

**6. По характеру использования аппаратных ресурсов**
* **Значение:** 64-разрядная ОС (x86-64 / AMD64).
* **Обоснование:** Полностью использует возможности современных процессоров с 64-битной адресацией, что позволяет адресовать более 4 ГБ оперативной памяти и эффективно работать с современным аппаратным обеспечение.
* **Наблюдение:** В свойствах системы указан тип: «64-разрядная операционная система, процессор x64».

## 2. Сравнение систем (Windows vs Ubuntu)

| Параметр | Собственная система (Windows) | Ubuntu на виртуальной машине |
| :--- | :--- | :--- |
| **Ядро** | Гибридное ядро NT (версия 10.0) | Монолитное ядро Linux (версия **5.19.0-21-generic**) |
| **Файловая система** | NTFS (основной системный раздел) | **ext4** (корневой раздел `/` на устройстве `/dev/sda3`) |
| **Установка программ** | Графические установщики (`.exe`, `.msi`), Microsoft Store, пакетный менеджер `winget` | Пакетный менеджер **APT** (`.deb` пакеты), менеджер **Snap**, центр приложений Ubuntu Software |
| **Оболочка** | Графическая оболочка Windows Shell (`explorer.exe`) | Графическая оболочка **GNOME Shell** |
| **Лицензия** | Коммерческая (Проприетарная / Proprietary) | Свободная (Открытое ПО, преимущественно **GNU GPL**) |

## 3. Разбор этапа хронологии ОС

*Выбранный этап: Изобретение систем разделения времени (Time-sharing) в 1960-х годах.*

**Аналитическая записка:**
В эпоху ранних ЭВМ господствовали системы пакетной обработки данных. Компьютер выполнял программы последовательно, из-за чего программисты часами или днями ждали результатов выполнения своих перфокарт, а дорогостоящий процессор простаивал во время операций ввода-вывода.
Предложенным решением стала концепция разделения времени (реализованная в CTSS и Multics), при которой процессор циклически переключался между задачами разных пользователей на короткие кванты времени.
Из этого решения в современных ОС развились механизмы вытесняющей многозадачности, планировщик потоков CPU, концепция интерактивного сеанса пользователя и псевдопараллелизм.
Цена данного изменения — существенное усложнение архитектуры ядра ОС, необходимость аппаратной поддержки защиты памяти программ друг от друга, а также неизбежные накладные расходы процессора на контекстное переключение (Context Switch) между задачами.
