# Отчет по практической работе: Каталог проекта shop

## Цель работы
Настройка прав доступа, владельцев, групп, а также специальных битов (SGID и Sticky-bit) в операционной системе Linux для обеспечения совместной безопасной разработки проекта командой из трех человек.

---

## 1. Настройка каталогов проекта и прав доступа

В ходе выполнения работы были созданы пользователи `alex`, `bella`, `chris` и общая группа `shop-dev`. Для каталогов проекта установлены следующие права:

*   **/srv/shop/src (права 2770):** Включен SGID-бит. Все новые файлы автоматически наследуют группу `shop-dev`. Доступ есть только у членов группы (разработчиков), остальным вход закрыт.
*   **/srv/shop/releases (права 2775):** Включен SGID-бит. Разработчики могут публиковать сборки. Пользователи вне группы (аналитик `chris`) имеют доступ только на чтение и просмотр.
*   **/srv/shop/uploads (права 3770):** Включен Sticky-bit. Общая папка для загрузок. Члены группы могут загружать файлы, но удалять чужие файлы запрещено операционной системой.

---

## 2. Результаты тестирования ограничений и безопасности

В ходе ручного тестирования безопасности системы были получены стопроцентно корректные ответы от ОС:

1. **Изоляция личных файлов:** При попытке пользователя `bella` прочесть секретный конфигурационный файл Алекса `config.env` (права `600`) система заблокировала доступ с ошибкой:
   `cat: /srv/shop/src/config.env: Permission denied`
   
2. **Ограничение прав аналитика:** Пользователь `chris`, не входящий в группу `shop-dev`, смог успешно прочесть опубликованный релиз `v1.txt`, однако при попытке зайти в закрытый каталог `src` или создать файл в `releases` закономерно получил отказ:
   `ls: cannot open directory '/srv/shop/src': Permission denied`
   `touch: cannot touch '/srv/shop/releases/photo.jpg': Permission denied`

3. **Работа Sticky-bit (Защита от удаления):** Пользователь `bella` создала файл в каталоге `uploads`. При попытке пользователя `alex` удалить этот файл система выдала ошибку:
   `rm: cannot remove '/srv/shop/uploads/photo.jpg': Operation not permitted`
   Это подтверждает, что Sticky-bit успешно защищает файлы пользователей от удаления коллегами по группе.

## 3. Ответы на контрольные вопросы по материалам занятия

*   **Строка `ls -l`:** Содержит тип объекта (файл/каталог) и три тройки прав (для владельца, группы и остальных). Дополнительно отображает спецбиты: символ `s` в тройке группы указывает на активный SGID (наследование группы каталога), а символ `T` в конце указывает на активный Sticky-bit (защита от удаления файлов не-владельцами).
*   **Каталог без прав `x` и без `r`:** Без флага `x` (выполнение) в каталог невозможно перейти с помощью команды `cd`, а также нельзя прочесть метаданные файлов внутри. Без флага `r` (чтение) операционная система запрещает вывод списка файлов внутри каталога через команду `ls`.
*   **Удаление и право `w` на каталог:** Возможность удаления или создания файла внутри каталога регулируется исключительно правами на запись (`w`) **самого родительского каталога**, а не правами на конкретный файл. Файл является лишь записью внутри структуры папки. Защитить файл от удаления пользователем с правами `w` на каталог можно только с помощью Sticky-бита.
*   **Форматы `chmod`:** Буквенный формат (например, `g+s`, `+t`) удобен для точечного добавления или изъятия конкретных прав без изменения остальных. Численный (восьмеричный) формат (например, `2775`, `3770`) позволяет жестко и быстро задать всю маску прав и спецбитов одной короткой командой.
