# 🛡️ Проект «Offboarding & Server Audit»

Репозиторий содержит курсовую работу по дисциплине **«Операционные системы и среды»** (курс 2, группа РПО/1). 
Проект посвящен симуляции реального инцидента информационной безопасности: отзыву прав уволенного администратора и комплексному аудиту сервера `ops-03`.

### 👥 Команда исполнителей:
* **Власян Давит** — зоны ответственности: управление учётными записями, аудит sudo, изоляция групп и контроль активных процессов.
* **Перфильева Арина** — зоны ответственности: миграция прав файловой системы (`/srv/devops`), изоляция конфиденциальных бэкапов, анализ setuid-уязвимостей.

---

## 🎯 Цели и задачи проекта
На основании заявки `SEC-2026-0088` для компании **ООО «Пятый склад»** были выполнены следующие критические процедуры:
1. **Деактивация скомпрометированного аккаунта:** Блокировка входа пользователя `kozlov` без удаления его домашней директории (сохранение цифровых улик).
2. **Терминация процессов:** Принудительное завершение всех фоновыми сессий и задач уволенного сотрудника.
3. **Безопасная передача инфраструктуры:** Назначение инженера `orlova` новым владельцем сервиса `/srv/devops` и ужесточение прав на деплой-ключи.
4. **Сбор и изоляция артефактов:** Поиск всех разбросанных по системе файлов пользователя, включая скрытые дампы баз данных в общих папках, и перенос их в изолированную root-директорию бэкапов.
5. **Анализ безопасности:** Поиск скрытых угроз и setuid-программ, которые могли быть использованы для закрепления в системе (Privilege Escalation).

## 📊 Результаты проверки и инсайты
В ходе финального автоматического тестирования было успешно сдано **15 из 17 проверочных тестов**. 

По результатам разбора, два оставшихся пункта (`FAIL`) локализованы и подробно описаны в документации:
* **Права на deploy.sh**: Связано с отсутствием флага исполнения `+x` внутри целевой директории во время симуляции работы от имени нового инженера.
* **Файл notes.txt**: На базовом стенде отсутствовал исходный файл заметок в домашней директории, из-за чего команда миграции не смогла физически переместить его в папку бэкапа. Способы устранения этих нюансов в продакшн-среде добавлены в отчет по ИБ.
